## [Linux 6.9 Regression: LUKS Suspend No Longer Wipes Encryption Keys from Memory](https://mathstodon.xyz/@iblech/116769502749142438) ⭐️ 7.0/10

A regression introduced in Linux kernel 6.9 prevents LUKS disk encryption keys from being wiped from memory during system suspend operations. This vulnerability exposes encrypted data to potential RAM scraping attacks during suspend, undermining disk encryption security guarantees for affected systems. The issue specifically affects cryptsetup luksSuspend functionality, which is primarily used in Debian-based distributions, while hibernation (suspend-to-disk) remains unaffected.

hackernews · IngoBlechschmid · Jul 2, 15:25 · [Discussion](https://news.ycombinator.com/item?id=48763035)

**Background**: LUKS (Linux Unified Key Setup) is the standard disk encryption framework for Linux systems. During suspend-to-RAM, system state is preserved in volatile memory, while hibernation writes encrypted RAM contents to disk. Key wiping during suspend was previously implemented to prevent physical access attacks.

**Discussion**: Community debate centers on whether this is a kernel bug or distribution-specific issue, with some noting suspend inherently retains keys in memory while others emphasize the security regression's severity. Users also discussed differing threat models for disk encryption.
